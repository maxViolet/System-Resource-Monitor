## Implemented behavior

- AI Core `Codex/`: `CodexContract` (the version, bucket, and window durations; the three request messages; the error envelopes; limits of 64 KiB per line, 32 messages, and JSON depth 16), `CodexResponseReader` (validates the version from `initialize.userAgent`, skips notifications, accepts only the rate-limit response with ID 2, identifies windows by duration, and rejects other buckets), `CodexLimitSnapshot`/`CodexLimitWindow` (`remaining = 100 − usedPercent`, used share only in 0–100), and `CodexLimitMonitor`. The monitor polls once per minute with no overlap. Sign-in, version, format, trust, timeout, and start failures are unavailable on the first failed poll. A network failure marks the last snapshot stale until three minutes after the last success, and an independent timer expires it at that deadline.
- Desktop `Adapters/Codex/`: `CodexClientLocator` implements ADR 0016: it canonicalizes the installer's entry point through its junctions, accepts only the pinned release path, rejects reparse points and untrusted write access, and verifies the Authenticode signer once per file identity while holding a lease that denies writes and deletes. `CodexAppServerSource` creates each client atomically inside a kill-on-close job, with only its standard-stream pipes inherited, fixed arguments, and the temp directory as working directory. It reads stdout and stderr concurrently (stderr limit 64 KiB) with a 10-second request timeout and 5 seconds' exit grace. On timeout, an output limit, or cancellation, it terminates the job and checks that the tree is empty within 2 seconds; an unconfirmed job remains owned and blocks later polls.
- Desktop `Bar/CodexSectionFormat` renders the ADR 0015 text, the `Codex (stale):` label, the unavailable text, and the tooltips. `BarWindow` adds a fixed-width Codex section and a one-shot countdown timer. `DesktopStartup` runs the Codex monitor as owner `codex-limits` with its own relay, after the metric monitor. `MetricRelay` is generic over the state type.
- The test host adds `--codex-probe <polls> <interval-seconds>`, which runs the production locator and source and prints classifications only. With the client's own arguments, it acts as a fake app-server for the process tests.

### Lifecycle tests

`SystemResourceMonitor.Desktop.TestHost.exe --bounded-shutdown` records `exit`, but its WPF dispatcher keeps waiting in `GetMessageW` inside `Application.Run`, and the process does not end. A test host built from unchanged `origin/main` (`d831f38`) in a separate worktree hangs the same way. A bar from another worktree held the session guard at first. With the user's approval it was closed through `WM_CLOSE`, and the hang persisted. The published Desktop app exits normally through `WM_CLOSE` with Codex polling active. `LifecycleProcessTests` are therefore **unverified** for this change and are not counted as passing.
