# B012 implementation plan for coding agents

Status: source selected under [ADR 0018](../../adr/0018-claude-usage-client-output.md), with client versions 2.1.304 and later accepted in [ADR 0022](../../adr/0022-claude-code-minimum-version.md) and the 2.1.311 local insights block qualified in [ADR 0025](../../adr/0025-claude-local-usage-insights.md). This plan implements [B012](../B12-claude-source.md) and hands its pinned contract to [B013](../B13-claude-limits.md). The [product plan](../../plan.md#3-deliver-subscription-limits), [provider adapter requirements](../../implementation-plan.md#provider-adapters), [ADR 0004](../../adr/0004-subscription-limits-in-first-release.md), [ADR 0017](../../adr/0017-claude-limit-display-in-codex-style.md), and [CONTEXT](../../../CONTEXT.md#language) remain authoritative.

## Source and boundaries

The selected source is the signed native `%USERPROFILE%\.local\bin\claude.exe` at version 2.1.304 or later ([ADR 0022](../../adr/0022-claude-code-minimum-version.md)). Run `auth status --json`, then `--safe-mode --tools "" --no-session-persistence --print --output-format json "/usage"` in a neutral directory. Read only stdout, stderr, exit code, and executable metadata. Never read credentials, browser state, transcript contents, internal caches, or undocumented endpoints. Raw output stays outside the repository and is deleted after evidence is sanitized. [ADR 0019](../../adr/0019-claude-child-image-load-policy.md) additionally requires the child image-loading policy for both invocations and no unprotected fallback.

The [2026-10-20 report](../../research/providers/claude-2026-10-20.md) rejected this output under the original exact-reset and three-way failure gates. The [2026-10-21 follow-up](../../research/providers/claude-2026-10-21.md) and ADR 0018 record the narrower contract: a 0%-used row can lack a reset, active reset text is minute precision with an observed one-minute difference, and a signed-out `/usage` response need not carry an error. An unknown failure becomes unavailable immediately; only a positively identified network response can retain stale values.

## Qualification and handoff

1. Verify the client path, canonical target, trusted owner, no reparse points, Anthropic signature, and version. Record the native installer's writable sandbox-group ACL exception from ADR 0018, the plan tier, and the official `/usage` rows without account identifiers.
2. Perform two independent non-interactive polls. Both must return the short window and all weekly rows observed in the official client. Active rows require reset text; 0%-used rows may omit it. Reject duplicate, unknown, malformed, or missing required rows.
3. Reconcile the displayed integer used shares with the official client in the same window. Calculate remaining as `100 - displayed used`; do not assert a hidden fractional rounding rule. Record reset text at its actual minute precision. The documented Claude subscription session limit is 300 minutes.
4. Exercise sign-out using an empty `CLAUDE_CONFIG_DIR` and `auth status --json`, without signing out the real account. Treat a logged-in `/usage` result without valid rows as unknown format. Classify a network error only after an explicit pinned client response is evidenced; do not infer it from missing rows or a stale file.
5. For each release, on the client version installed at that time and with no other account work, run ten polls one minute apart; verify no model turns, API duration, cost, session or transcript creation, or changed used shares. Minute-level reset display variation is recorded rather than treated as usage. Repeat this check with the B013 adapter.
6. Record a dated sanitized report and link it from the package README. Pin any unverified plan tier, locale, version, network, access-revocation, and artifact gate. B013 owns production parsing, source isolation, polling, expiry, presentation, and Windows desktop acceptance.

## B013 contract

The JSON envelope must report `local_command: usage`, `num_turns: 0`, `duration_api_ms: 0`, `total_cost_usd: 0`, and `is_error: false`. Only its `result` text is parsed. Recognized subscription rows are `Current session`, `Current week (all models)` and any model-specific `Current week (...)`. A newly appearing monthly or other row is unknown format until qualified separately. The 2.1.311 local insights block is the sole exception: ADR 0025 bounds its heading, notice, and row grammar after the required subscription windows; its percentages are discarded. Each recognized row carries an integer `N% used` from 0 through 100 and, when active, `· resets <date/time> (<zone>)`. Missing reset is accepted only for 0% used. The snapshot retains all weekly windows and their observed reset times, selects the highest used share (lowest remaining share) for the bar, and leaves month unqualified. Exact text was observed on client versions 2.1.304 and 2.1.306 and applies to every accepted version; an older version or a changed row is unavailable, never silently accepted.
